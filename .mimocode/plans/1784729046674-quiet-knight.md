# Fix: Password Gate Not Showing on Shared Link

## Root Cause

When a guest visits a direct link like `/savethedate/Mark-She`, the password gate doesn't show even though password protection is enabled. It works correctly with `?guest=1` (admin preview).

The issue is in `InvitationRenderer.jsx` lines 92-99:

```js
const [passwordUnlocked, setPasswordUnlocked] = useState(() => {
    if (!passwordProtected) return true;     // line 94
    if (previewMode) return false;           // line 95 - always shows in preview
    // ...checks localStorage for prior unlock
});
```

**Two scenarios cause the bug:**

1. **Stale localStorage**: Guest previously visited the link BEFORE password was enabled. At that time, `passwordProtected` was `false`, so line 94 set `passwordUnlocked = true`. Even after admin enables password, the stale `true` persists in the component state (useState initializer only runs once on mount). On next page load, it checks localStorage which may have `qb_pw_unlock_<slug> = '1'` from a prior session.

2. **No localStorage clear on toggle**: When admin toggles password protection ON, no code clears the guest's existing `qb_pw_unlock_<slug>` localStorage entry. So if a guest ever unlocked before, they bypass the gate forever.

## Fix

### Change 1: Clear stale unlock when password protection is enabled

**File:** `frontend/src/pages/client/InvitationBuilder.jsx` (line 248, `handleSavePassword`)

After the `eventService.update()` call succeeds, if `password_protected` is `true`, clear any stale localStorage unlock:

```js
const handleSavePassword = async ({ password_protected, password }) => {
    const slug = form.slug || slugFromEventName(form.event_name);
    // ... existing code ...

    if (eventId) {
      await eventService.update(eventId, buildInvitationPayload());
    } else {
      // ... existing code ...
    }

    // Clear stale unlock so guests see the fresh password gate
    if (password_protected) {
      try {
        localStorage.removeItem('qb_pw_unlock_' + slug);
        sessionStorage.removeItem('qb_pw_unlock_' + slug);
      } catch {}
    }
};
```

### Change 1b: Same fix in InvitationManage.jsx

**File:** `frontend/src/pages/client/InvitationManage.jsx` (line 753-755)

The inline `onSavePassword` handler also needs the localStorage clear:

```js
onSavePassword={async (data) => {
    await eventService.update(event.id, { invitation: data });
    if (data.password_protected) {
        try {
            localStorage.removeItem('qb_pw_unlock_' + event.slug);
            sessionStorage.removeItem('qb_pw_unlock_' + event.slug);
        } catch {}
    }
}}
```
